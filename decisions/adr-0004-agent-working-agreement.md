# ADR-0004: エージェントへの指示の持ち方（約束・CLAUDE.md の上限・検査化・セッションの単位）

**日付**: 2026-11-05
**ステータス**: 採用
**関連**: [ai/COMMITMENTS.md](../ai/COMMITMENTS.md)（約束の正本）、[ai-dev-standards Governance](https://github.com/jazmf-dx/ai-dev-standards/blob/main/standards/governance/README.md)、[ADR-0001](adr-0001-web-apps-monorepo.md)、[ADR-0002](adr-0002-pr-gates-runner-and-staging.md)

## コンテキスト

ai-dev-platform と各アプリの `.claude/rules` は、Bedrock の従量課金の時期にトークンを節約する目的で作った。サブスクに変えてからその優先度は下がり、いま規約に価値があるのは「エージェントの出力を正しい向きにする」「人が読まなくても機械が止める」の 2 点だけになった。ところが 2026-11-05 の全体レビューで、どちらも満たしていないことが分かった。

- 「返答は日本語」「判断は質問形式で聞く」という基本的な指示が、どのリポジトリの CLAUDE.md にも `.claude/` にも書かれていない。ターミナル時代はユーザー設定や会話で伝えていたが、アプリ版のクラウドのセッションにはそれが無く、毎回のセッションが何も知らない状態で始まる
- 常時読み込まれる文書は dx-portal だけで約 1,680 行。そのうち約 700 行（2026-07 の監査レポート・Alpine を前提にしたフォーム検証とモーダルの rules）が、ADR-0010 と逆の指示をしている
- agents 18 本中 12 本が別プロジェクト（FastAPI・SQLAlchemy・DADS・Windows パス）の持ち込みで、orchestrator がそこへ委任する。skills 6 本中 3 本が壊れている
- 権限の一覧は 6 か所以上に複製され、「8 つ」と「10 個」が混在する。ADR 番号が 3 組重複している（採番が「最大 +1」で並行ブランチと衝突する）
- 複数リポジトリを束ねたセッションでは各リポジトリの `.claude/settings.json`（フック・許可）が読まれない。クラウド環境（許可ドメイン・トークン・セットアップ）は未定義で、UI Kit の取得が 401 で落ちる
- 「質問して止まる」は、クラウドのセッションが「ユーザーが見ていない間に進める」設計に寄っているため、一般論で書いても効きにくい

## 決定

1. **約束を 1 ブロック（10 行以内）にし、全リポジトリの CLAUDE.md の先頭に同じものを置く。** 正本は [ai/COMMITMENTS.md](../ai/COMMITMENTS.md)。中身は、返答と成果物は日本語／止まって質問する場面の列挙／それ以外は自分で決めて何を決めたか書く／コミットは差分の提示から／結論を先に。配布は symlink や submodule ではなく**コピー**で、ai-dev-platform のスクリプトが差分を検査する。
2. **CLAUDE.md は 100 行以内。** 書くのはアプリ固有の差分（何のアプリか・触る前に知るべき前提・コマンド・固有の禁止事項）だけ。手順は docs/、経緯は ADR と git 履歴、時系列の注意書きは書かない。数値（権限の数・テンプレート数など）を本文に持たず、正本へのリンクにする。
3. **ルールは検査に置き換える。** 文書に書いてあるが機械で止めていないものは、`test_native_form_inputs.py` と同じ「既存は ALLOWED で件数を固定、新規はゼロ」の方式でテストにする。最初の対象は固定色・Alpine（`x-data`）・素の `<select>`・色の直書きボタン・ADR 番号の重複・Markdown のリンク切れ・サイドバーと権限の整合（既存）。検査にできないルールは、原則 1 枚に残すか捨てる。
4. **`.claude/rules` は paths 条件付きのものだけ残す。** 常時ロードは CLAUDE.md と約束だけ。監査レポート・計画・ハンドオフは `.claude/` に置かず docs/ に置く。agents と skills は対象スタック（Django・htmx・React Islands・UI Kit）に合うものだけ残し、合わないものは削除する。
5. **1 リポジトリ = 1 セッション。** 横断の作業も、必要なリポジトリだけを足す。モノレポ（[ADR-0001](adr-0001-web-apps-monorepo.md)）なら自然にそうなる。
6. **クラウド環境を 1 つ定義する。** 許可ドメイン（GitHub Packages・PyPI・npm）、`GITHUB_PACKAGES_TOKEN`（Network secrets）、セットアップスクリプト（`uv sync`・`bun install`・フックの導入）を環境の設定に置く。各リポジトリの SessionStart フックは、この環境で動くことを前提に書く。
7. **モードの使い分けを決めておく。** 設計・方針・ADR は Plan モード（計画の承認で必ず止まる）、実装は Accept edits、整理・検査・ドキュメントの同期は Auto。モデルのティア（設計と重要なレビューは本体、通常の実装は Sonnet、検証は Haiku）は desktop-platform Governance §3.1 を Web にも適用する。
8. **人が見る単位を変える。** 人はコードの差分を読まない。見るのは決定（ADR）・ステージングの画面（[ADR-0002](adr-0002-pr-gates-runner-and-staging.md)）・検査の結果。コードのレビューは code-review スキルと CI に任せる。
9. **効率は「人のレビュー負荷と手戻り」で測る。** トークンの節約のために文書を圧縮することは目的にしない。

## 結果

- どのセッションでも同じ約束が先頭で読まれ、「日本語」「止まる場面」が守られているかを文面で確かめられる
- 常時ロードの量が減り、矛盾した指示が消える。エージェントの出力が規約と逆を向く原因がなくなる
- ルールの追加は「検査を書く」ことになり、文書だけのルールは増えない
- 約束の文面を変えるときは COMMITMENTS.md を変え、スクリプトで全リポジトリに配る。CLAUDE.md の先頭を個別に編集しない
- 最初の作業（dx-portal）: 監査レポートを docs/reviews へ移す、Alpine の rules を「既存のみ」に限定、models.md の paths を `views/**` へ、agents 12 本の削除、skills 3 本の修正、ADR 番号重複の解消と検査、CLAUDE.md の数値を参照に置き換え、project-context の更新
